# 周报归档新闻重置与历史档案迁移设计

## 背景

归档个人周报时，报告快照已保存 AI 新闻，但实时工作区仅清空了自定义页，未清空当前周 AI 新闻，导致新周第三页继续展示已归档内容。

此外，admin 与 leo 后续被合并为同一报告数据源（admin）。合并前 leo 已归档的 `2026-07-27` 周报仍保存在 leo 的旧数据文件中，因未迁移到共享数据源而没有出现在当前档案入口。

## 目标

1. 归档完成后，当前个人报告恢复为三个系统页，AI 新闻正文清空。
2. 新周仍保留已抓取的新闻候选，便于重新选择和生成。
3. 将现有 leo 历史档案合并到共享档案；保留已有共享档案，绝不覆盖同周或其他周的版本。

## 设计

### AI 新闻重置

`ReportNewsStore` 提供按周清除已发布新闻与草稿的操作。归档 API 成功保存报告快照后，调用该操作清理被归档周的实时新闻内容。候选新闻字段不受影响。

归档 API 的顺序为：读取当前周新闻、创建报告快照、清空该周新闻正文。任一步失败都返回错误，不会把未归档内容提前清掉。

### 共享历史档案迁移

在生产数据中执行一次、可重复运行的迁移：读取旧 leo 数据源的 `archives`，按 `weekStart` 合并进入 admin 共享数据源。

- 共享源不存在该周：完整复制该周档案与全部版本。
- 共享源已存在该周：仅追加 ID 未重复的历史版本，不改动当前正式版标记。
- 迁移不会复制旧 leo 的实时数据、当前自定义页或当前新闻，避免覆盖现在的工作区。
- 迁移前创建带日期的生产数据备份；迁移后核对两个周次均能通过档案 API 读取。

## 验证

新增存储层回归测试：归档后报告自定义页和实时新闻都被清空、候选新闻仍保留；重复迁移不会产生重复档案或版本。部署前运行完整 Node 测试集；部署后查询生产档案 API 与数据文件，确认 `2026-07-27` 和 `2026-08-03` 均存在。

## 非目标

- 不删除任何历史档案、候选新闻或既有正式版。
- 不改变普通用户的独立报告数据。
