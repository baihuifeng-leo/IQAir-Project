# 素材中心与详情长图设计规格

## 目标

在现有电商工作台中，将一级功能“素材质检”升级为“素材中心”，保留现有素材质检能力，并新增“详情长图”子功能。用户填写受支持的天猫或淘宝商品详情链接后，工作台使用服务器上的受控 Chromium 和已登录淘宝会话识别商品详情素材，完成完整性校验，将全部图片统一满宽、等比例拼接为唯一 PNG，并提供下载。

同时新增独立的一级功能“平台账号”，用于查看和管理当前淘宝/天猫会话。第一阶段只实现淘宝/天猫连接，但平台会话接口必须允许后续增加拼多多、抖音和微盟连接器。本阶段不开发多店库存、价格、订单或经营状态功能。

## 范围

### 本阶段包含

- 原一级导航“素材质检”更名为“素材中心”。
- 素材中心提供“素材质检”和“详情长图”两个子入口。
- 原素材质检页面、接口、权限、词库、历史数据和 OCR 流程保持兼容。
- 新增“平台账号”一级页面。
- 管理员可建立、验证、重新登录和清除淘宝/天猫受控浏览器会话。
- 所有已登录工作台用户可查看平台账号状态。
- 用户可提交受支持的天猫或淘宝商品详情 URL，并异步生成一张完整 PNG。
- 详情图片统一铺满输出宽度并保持原始比例。
- 任务进度、失败原因、结果下载和近期任务可在详情长图页面查看。
- 浏览器会话、临时素材、任务结果和任务元数据存放于运行时数据目录。
- 完成后在功能分支提交、合并到 `main` 并推送 GitHub；生产部署不属于本次自动执行范围。

### 本阶段不包含

- 拼多多、抖音、微盟的实际登录或授权。
- 多平台库存、价格、订单或店铺状态同步。
- 竞品批量抓取或批量详情拼接。
- 绕过淘宝或天猫验证码、风控、访问限制。
- 商品主图、SKU 选择器、评价、推荐、店铺信息或页面导航的导出。
- GIF 动画和视频流导出；GIF 只取静态首帧，视频只在详情内容中存在可用封面时使用封面。
- 自动部署到生产服务器。

## 信息架构与导航

### 素材中心

现有一级入口“素材质检”更名为“素材中心”。鼠标悬浮或键盘聚焦该入口时显示下拉抽屉，包含：

1. 素材质检
2. 详情长图

点击“素材中心”主入口默认打开素材质检，保持原用户操作习惯。下拉抽屉必须支持鼠标和键盘操作；焦点进入抽屉后不得因主入口失焦而立即关闭，按 `Escape` 可关闭并将焦点归还主入口。窄屏或无悬浮能力的设备使用点击展开。

素材质检现有功能标识、权限检查和页面状态不能因为导航重命名而改变。内部模块标识可继续沿用稳定的 `materialcheck`，避免迁移运行时数据。

### 平台账号

新增独立一级入口“平台账号”，不放在素材中心抽屉内。页面展示账号卡片，包括：

- 平台名称与账号备注
- 登录状态
- 最后验证时间
- 当前占用任务
- 最近错误或失效原因

所有登录用户均可查看状态。只有管理员可执行“登录”“重新登录”“验证状态”“清除会话”。服务端必须再次校验管理员权限，不能只依赖前端隐藏按钮。

第一阶段只显示已实现的淘宝/天猫账号卡片。不为未实现的平台提供可操作占位按钮。

## 受控浏览器与平台会话

### 会话边界

平台会话使用通用接口，详情长图模块不得直接读取 Cookie 或浏览器配置目录。接口至少表达以下职责：

```text
getStatus(platform, accountId)
beginLogin(platform, accountId)
verify(platform, accountId)
runWithSession(platform, accountId, task)
clear(platform, accountId)
```

第一阶段实现 `taobao` 平台连接器和一个默认账号。账号标识仍保留在接口与存储结构中，未来增加多个店铺账号时不需要改变调用方。

### 登录流程

管理员发起登录后，Worker 启动 Chromium 的持久化浏览器上下文并打开淘宝登录页面。工作台通过受保护的短时截图或图像端点展示当前二维码。二维码响应不得被公共缓存，不得写入静态目录，并且只能由当前已登录管理员读取。

管理员扫码并在平台完成登录后，Worker 验证淘宝或天猫受保护页面是否可访问，再将状态切换为“已登录”。登录超时、二维码过期、验证码或风控均返回明确状态，不自动绕过。

### 状态模型

账号状态包括：

- `logged_out`：未登录
- `waiting_for_scan`：等待扫码
- `verifying`：验证中
- `ready`：已登录且最近验证成功
- `challenge_required`：需要管理员处理验证码或风控
- `expired`：会话已失效
- `unavailable`：Chromium 或 Worker 不可用

状态记录只保存非敏感元数据：账号标识、状态、更新时间、最后验证时间和经过清理的错误码。Cookie、Token、完整页面 HTML、二维码内容和浏览器内部信息不得进入日志、审计摘要或 API JSON。

### 持久化与并发

浏览器用户数据目录位于 `DATA_DIR/platform-sessions/taobao/<accountId>/`，必须加入 Git 和部署复制的排除规则。会话目录权限限制为工作台服务账号可读写。

同一个账号同一时间只允许一个浏览器操作，包括登录、验证和详情识别。其他任务进入有界队列或返回“账号正在使用”，不得并行操作同一个持久化上下文。Worker 异常退出后必须释放占用锁，并将账号状态更新为 `unavailable` 或需要重新验证的状态。

## 详情长图用户流程

1. 用户进入“素材中心 → 详情长图”。
2. 用户填写商品详情 URL，选择可用的淘宝/天猫账号；第一阶段默认选中唯一账号。
3. 服务端校验 URL 和用户权限，创建异步任务。
4. Worker 使用指定平台会话打开商品页并验证没有落入登录、验证码、风控或错误页。
5. 页面适配器找到可信的商品详情根节点，收集详情素材及候选地址。
6. Worker 下载并解码全部素材，持续报告素材总数、当前项和阶段。
7. 只有全部必需素材预检成功后才计算布局并生成 PNG。
8. 成功后页面提供下载；失败时显示结构化原因且不创建残缺 PNG。

关闭页面不会取消任务。用户重新进入详情长图页面时可恢复查看近期任务。用户可以取消尚未进入下载完成状态的自有任务。

## URL 与页面安全

服务端只接受 HTTPS 商品详情 URL。第一阶段允许的入口域名为：

- `detail.tmall.com`
- `item.taobao.com`

提交 URL 时解析并规范化商品 ID，忽略非必要的跟踪参数。受控浏览器每次主文档导航和重定向都重新检查目标：只允许淘宝、天猫登录域名和经明确列举的商品详情同源路径。不得允许任意 URL、IP 地址、用户信息形式主机名、非标准端口、`file:`、`data:` 或其他协议。

图片请求只接受从已验证商品详情 DOM 提取的 HTTPS 地址，并限制到明确允许的阿里图片域名集合。响应必须是可解码图片且不得超过配置的单项和任务总大小上限。

## 页面识别

天猫与淘宝使用独立、可测试的详情根选择器，并共享内容遍历、排除规则和图片候选解析。找不到可信根节点时任务失败，不退化为选择全页面中图片最多的容器。

每张图片按 DOM 顺序生成候选地址集合，来源优先级为：

1. `currentSrc`
2. `srcset` 中从高分辨率到低分辨率的地址
3. `src`
4. 已支持的懒加载属性，例如 `data-ks-lazyload`、`data-lazyload`、`data-src`、`data-original`、`data-url`

候选需去重并过滤空值、透明像素占位、内联占位图和非 HTTPS 地址。协议相对地址补全为 HTTPS。不得猜测性改写 `~crop...~`、签名参数或文件扩展名大小写。

识别目标仅为商品详情描述区域中的图片、基础文本、表格和视频封面。推荐、评价、店铺、导航、浮层和主商品信息必须排除。

受控浏览器可以在其独立页面中滚动以触发懒加载；该滚动不会影响用户自己的浏览器窗口。滚动应逐步覆盖详情区域，等待 DOM 与图片数量稳定，并设置总超时。达到超时时如果不能证明详情完整，任务失败而不是导出部分结果。

## 素材预检与错误处理

每个图片区块保存有序候选地址。Worker 使用当前浏览器会话和页面上下文依次请求候选；每个唯一候选最多请求两次。HTTP 失败、响应类型错误、空内容、超过大小限制或图片解码失败时尝试下一个候选。

预检阶段记录最终可用 Blob、真实像素宽高和实际来源地址。只有所有必需图片均有可用候选时才进入合成。

任一必需图片全部候选失败时：

- 停止任务并释放已取得的图片资源；
- 不调用结果下载生成流程；
- 不在 PNG 中绘制红字或错误占位；
- 在详情长图页面显示素材序号、经过脱敏/长度限制的候选地址和最后错误；
- 保留“重新尝试”入口。

登录失效、验证码、页面结构不支持、资源失败、超时、取消和 Worker 异常使用不同错误码，前端不得全部显示为笼统的“Failed to fetch”。

## 拼接规则

第一阶段采用统一满宽布局。输出宽度取全部成功解码详情图片真实宽度的最大值。基础文本、表格和视频封面不得扩大输出宽度。

每张图片按以下规则绘制：

```text
drawWidth = outputWidth
drawHeight = round(sourceHeight * outputWidth / sourceWidth)
x = 0
```

图片保持原始宽高比，不裁切、不拉伸、不居中、不产生左右白边。图片之间不增加额外间距。原始素材内部自带的白色像素保持不变。

基础文本和表格在相同输出宽度内绘制。GIF 输出静态首帧。视频只使用成功取得的封面，并以非破坏性的方式标识为视频封面；缺少必需封面时按资源预检失败处理。

极长输出继续采用固定高度条带绘制和流式 PNG 编码，避免单块 Canvas 高度限制。跨条带图片必须连续，不得裁切、重复或出现接缝。最终只生成一个 PNG 文件。

## 任务、结果与清理

详情任务至少包含：任务 ID、创建用户、平台账号、规范化商品 URL、商品 ID、阶段、进度、素材计数、创建/更新时间、结果文件元数据和结构化错误。任务状态持久化在 `DATA_DIR`，以便页面刷新后恢复。

结果文件只能由已登录用户下载；普通用户只能查看和取消自己的任务，管理员可查看全部任务。下载响应使用安全文件名并设置正确的 PNG 类型。

临时文件在任务结束后立即清理。成功结果和近期任务采用可配置保留期，默认保留 24 小时；服务启动和定时清理都会删除过期文件。不得清理浏览器会话目录或现有素材质检数据。

## 进程与部署

受控浏览器和详情处理运行在独立 Worker 进程中，不在主 HTTP 请求处理线程执行。主服务负责鉴权、任务 API、状态持久化和 Worker 生命周期。Worker 崩溃不得中断工作台主服务或 OCR Worker。

仓库目前没有 npm 构建流程。本功能允许新增运行时浏览器自动化与图片处理依赖，但必须：

- 固定依赖版本并提交锁文件；
- 在 `install.sh` 中安装 Chromium 及必要系统库；
- 更新 systemd 的可写目录和运行权限；
- 保持前端为仓库现有原生 JavaScript/CSS 结构，不引入前端构建工具；
- 在 README 中记录首次安装、会话登录、故障排查和磁盘占用。

## 验收标准

### 回归保护

- 现有素材质检词库、上传、OCR、历史记录和权限测试通过。
- 其他一级功能及现有登录、SSE、备份恢复行为不受影响。
- “素材中心”默认进入素材质检。

### 导航与权限

- 素材中心抽屉可用鼠标、键盘和点击方式操作。
- 平台账号状态对登录用户可见，管理操作仅管理员可用且服务端强制鉴权。
- 普通用户不能读取二维码、Cookie、浏览器目录或其他用户的详情任务结果。

### 平台会话

- 管理员可完成淘宝扫码登录并在服务重启后复用会话。
- 登录失效、验证码、Chromium 不可用和账号占用具有不同状态及提示。
- 同一账号不会并行运行多个浏览器操作。

### 详情长图

- 用户提供的天猫测试链接能够识别详情区域并生成唯一 PNG。
- 选取一个正常淘宝商品链接完成同等人工验收。
- 详情素材顺序与页面一致，不包含主图、评价或推荐。
- 不同宽度图片全部铺满输出宽度并保持原始比例，无左右白边。
- 任一必需素材失败时不生成 PNG，页面显示具体错误且不存在红字占位图片。
- 超长详情跨条带连续，无裁切、重复或接缝。
- 页面刷新后仍可查看任务进度和下载未过期结果。

### 工程验证

- 新增的单元和集成测试全部通过。
- 现有 `node merge.test.js` 与 `node materialcheck.test.js` 通过。
- 开发环境可启动主服务、浏览器 Worker，并完成一次受控登录和真实链接端到端测试。
- 安装脚本在支持的 Ubuntu 环境中可重复执行。
- 功能分支合并到 `main` 后推送到配置的 GitHub 远端；不执行生产部署。
