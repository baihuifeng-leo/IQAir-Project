# 周报档案独立窗口与新闻周绑定设计

## 目标

从周报档案查看历史版本时，在独立浏览器窗口打开，只读浏览不改变当前个人报告的编辑状态；归档快照只保存同一归档周的 AI 新闻，不能回退引用其他周内容。

## 现状与根因

当前“查看”调用主页面的 `openArchive()`，把历史快照替换到主页面的 `data` 和 `news` 状态中。因此编辑器被历史报告占用，并出现“返回当前报告”操作。

归档接口创建快照时使用 `newsData.weeks[input.weekStart] || summary.news`。当目标周没有新闻时，`summary.news` 会取当前周的新闻，造成 2026-07-27 档案保存了 2026-08-03 的内容。

## 方案

### 独立档案窗口

- 档案抽屉中的“查看”以 `window.open()` 打开个人报告专用历史 URL，并携带 `weekStart`、`versionId` 和 `archive=1` 查询参数。
- 历史窗口启动时读取该查询参数，加载指定快照，设为只读，并隐藏档案入口和会改变实时报告的动作。
- 主窗口不调用 `openArchive()`，所以保留正在编辑的数据、当前页码、新闻候选和未保存界面状态。
- “创建修订”仍在主窗口创建新版本；创建成功后在独立窗口打开该新修订版。修订窗口可保存它自己的快照，不影响主窗口。

### 周新闻绑定

- 归档创建接口只读取 `newsData.weeks[input.weekStart]`。
- 若该周没有已生成新闻，归档快照中的 `news` 为 `null`，前端显示该周未生成 AI 新闻；禁止以任何其他周新闻替代。
- 不改变已有新闻候选或当前实时周新闻的保存策略。

### 生产历史数据修复

- 精确检查共享报告档案，仅处理 `2026-07-27` 的版本。
- 若该版本快照新闻的 `weekStart` 不等于 `2026-07-27`，将该快照新闻设为 `null`。
- 执行前创建日期命名的 JSON 备份；不修改 2026-08-03 或后续档案。

## 验收标准

1. 点击“查看”后，当前个人报告页面不切换、不会出现“返回当前报告”，而是打开独立历史窗口。
2. 新窗口展示指定周与指定版本的快照，且默认只读。
3. 新建修订版在独立窗口编辑并保存，不覆盖主窗口实时数据。
4. 新归档在对应周没有新闻时显示空新闻状态，绝不显示其他周内容。
5. 生产的 2026-07-27 档案不再展示 2026-08-03 新闻；修复前的数据有可恢复备份。
6. 已归档报告现有的母版冻结规则不被破坏。

## 测试

- 为归档创建增加回归测试：目标周无新闻时，归档快照新闻为 `null`。
- 为前端静态/UI 回归测试：查看操作使用独立窗口链接，历史模式从 URL 加载指定版本，主模式保留原有刷新入口。
- 运行完整 Node 测试套件、`git diff --check`，部署后检查生产健康接口与共享档案快照。
