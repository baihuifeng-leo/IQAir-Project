# EC-Workbench 生产迁移设计：192.168.2.7 → 192.168.2.8

## 目标与边界

将当前运行在 192.168.2.7 的 EC-Workbench 无损迁至 192.168.2.8。外部入口仍为 `iqair.leobai.com:44432`；用户在验证 .8 后自行将反向代理上游从 `.7:8090` 改为 `.8:8090`。

本迁移不是容器化或应用重构；不改应用功能、不变更数据结构、不更换 OCR 引擎。删除 .7 不属于本次切换步骤，须在观察期和独立备份完成后另行确认。

## 已验证前提

两端均为 Ubuntu 24.04、x86_64 和 Python 3.12.3。源端 Node 为 22.23.1，目标端当前为 20.20.2，因此目标须先升级到 22.23.1 后再启动服务。目标端约有 9.9GB 可用空间；源端的生产代码和 Python 环境合计约 1.3GB，生产数据约 455MB。

## 资产边界

| 类别 | 源端 | 目标端 | 策略 |
| --- | --- | --- | --- |
| 生产代码与 Python venv | `/opt/workbench` | `/opt/workbench` | 保留已验证的运行时，精确复制 |
| 业务数据与上传文件 | `/var/lib/workbench` | `/var/lib/workbench` | 预同步一次；停源后最终镜像同步 |
| OCR 模型与缓存 | `/var/lib/workbench/.paddlex`、`.cache` | 同路径 | 随数据目录完整迁移，不重新下载 |
| systemd 单元 | `/etc/systemd/system/workbench.service` | 同路径 | 从已验证单元复制，启用但预同步期间不启动 |
| AI 服务环境文件 | `/etc/workbench/ai.env` | 同路径 | 仅受控文件复制；不读取、显示或提交内容 |

`/var/lib/workbench` 同时包含 `.session-secret`。保留它可以避免切换后强制全部用户重新登录；该文件的内容绝不进入日志、文档或 Git。

## 预迁移设计

1. 在 .8 创建 `workbench` 系统用户及目录，赋予与 .7 等价的所有权和最小写权限。
2. 安装/核验 Node 22.23.1；不以 Node 20 的“理论兼容”替代版本一致性。
3. 通过保留权限、链接、ACL/xattr 和数值 UID/GID 的同步方式复制 `/opt/workbench` 与 `/var/lib/workbench`，目标明确为上述两个目录；不对源端使用删除操作。
4. 仅在 .8 做本机离线验收：systemd 配置、服务启动、端口 8090、数据加载、OCR worker 进程和一份既有图片的实际识别。预同步期间不让 .8 正式服务长期运行，以免双端定时任务同时写数据。
5. 预同步结果按目录清单、容量、所有权和抽样校验和复核；任何异常都先停止，保持 .7 继续提供服务。

## 切换与回滚

维护窗口内执行以下顺序：

1. 记录 .7 服务状态与源、目标目录清单；停止 .7 的 `workbench.service`，确认 node 与 Python OCR worker 已退出。
2. 对 `/opt/workbench`、`/var/lib/workbench` 进行最终同步并核验。这是唯一保证所有 JSON/JSONL、上传和 OCR 缓存处于同一时间点的步骤。
3. 在 .8 启动 `workbench.service`，核验服务状态、日志无启动错误、端口监听、页面与关键数据加载；执行 OCR 实测。
4. 用户将反向代理上游切至 `.8:8090`，再从外部域名完成登录和核心功能冒烟测试。

任一验证失败时：停止 .8 服务，把反向代理切回 `.7:8090`，重新启动 .7 服务。由于最终同步不修改源端，回滚不会依赖从 .8 反向复制数据。

## 验收标准

- .8 上 `workbench.service` 持续 active，Node 与 Python OCR worker 均运行。
- UI 能加载，已有用户、业务数据、评论/报表/素材质检记录和上传文件均可访问。
- 一份已有素材的 OCR 可完成并产出预期文本/关键词匹配结果；不触发模型下载。
- 外部域名经反向代理访问正常，登录 session 连续有效。
- .7 保持关停但不删除，直到观察期结束。

## 删除 .7 的前置条件

1. .8 连续稳定运行并经用户确认。
2. 独立于两台 LXC 的最终备份已完成并可恢复，例如 Proxmox Backup、NAS 或宿主机快照。
3. 已确认所有 Git 分支/提交已推送；保留 `.7` 中可能存在的机器专属 agent 状态、脚本、日志或备份的清单和去向。
4. 用户再次明确授权删除 .7 容器。
